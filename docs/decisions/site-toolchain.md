# زنجیرهٔ ساخت سایت راست‌به‌چین — RTL site toolchain

**وضعیت:** تصویب‌شده — [تیکت #9](https://github.com/vali-mohammadi/patternfly-design-fa/issues/9)
**پیش‌نمونهٔ زنده:** [`docs/decisions/prototype/index.html`](./prototype/index.html) — به‌جای تصمیم روی کاغذ، یک صفحهٔ واقعی ساخته و در مرورگر بازبینی شد.

## چه چیزی بازبینی شد

پیش‌نمونه یک صفحهٔ کامپوننت واقعی («مسیر راهنما») را با تمام قراردادهای تصویب‌شدهٔ پروژه
پیاده کرد و در مرورگر رندر شد: `dir="rtl"` روی `<html>`، قلم Estedad (از طریق Google
Fonts)، خواص منطقی CSS (`border-inline-start`، `margin-inline-*`)، پنج نوع callout طبق
[teaching-layer.md](./teaching-layer.md)، یادداشت استاندارد تصویر LTR، اعداد فارسی
(«۹ مرداد ۱۴۰۴»)، و جداسازی دوجهته (bidi isolation) برای شناسه‌های لاتین و بلوک کد
(`scaleX(-1)`) داخل جملهٔ فارسی.

**نتیجهٔ بازبینی بصری:** همه‌چیز درست رندر شد — چیدمان راست‌به‌چین، جهت نشانگر مسیر راهنما،
رنگ نوار کناری callout در سمت درست (بدون نوشتن دستی `left`/`right`)، و جداسازی صحیح متن
لاتین تعبیه‌شده. تنها مشکل، بارگذاری نشدن یک تصویر نمونه از یک مسیر GitHub raw بود که ربطی
به موتور رندر ندارد.

## تصمیم — ابزار ساخت سایت

**[Eleventy (11ty)](https://www.11ty.dev/)** به‌جای Jekyll.

| معیار | Jekyll (فعلی) | Eleventy |
|---|---|---|
| پشتیبانی RTL | هیچ — باید از صفر ساخته شود | هیچ — باید از صفر ساخته شود (یکسان) |
| تطابق با front matter محتوای ما | خوب (Jekyll هم YAML front matter دارد) | خوب — دقیقاً همان الگو |
| زنجیرهٔ ابزار | روبی (Gemfile با `mdl 0.4.0`، Travis روی Node ۴ — بسیار قدیمی) | Node.js — همان زنجیرهٔ ابزار اسکریپت‌های موجود پروژه (`script/*.js`) |
| پیچیدگی برای یک نگهدارنده | متوسط (Liquid) | کم — قالب‌های Nunjucks ساده، بدون build پیچیده |
| نیاز به تعامل (playground کامپوننت) | محدود | در آینده با یک لایهٔ سبک جاوااسکریپت قابل افزودن، بدون تغییر معماری |
| سرمایه‌گذاری فعلی در Jekyll | ناچیز — کل `_config.yml` یک خط است | — |

**چرا نه یک فریمورک سنگین‌تر (Astro/Next):** این یک سایت مستندسازی محتوامحور است، نه یک
اپلیکیشن. Eleventy همان کاری را که لازم است انجام می‌دهد — رندر مارک‌داون + قالب — بدون بار
اضافهٔ runtime جاوااسکریپت که این پروژه فعلاً به آن نیازی ندارد.

## پیامدهای مستقیم برای پیاده‌سازی (از پیش‌نمونه)

- `dir="rtl"` روی `<html>`، نه با CSS — طبق [mirror-table.md](./mirror-table.md#پیاده‌سازی).
- توکن‌های CSS باید از خواص منطقی استفاده کنند، نه `left`/`right` مستقیم.
- شناسه‌های لاتین و بلوک‌های کد باید `direction: ltr; unicode-bidi: isolate;` بگیرند تا در
  جملهٔ فارسی به‌هم نریزند — این الگو مستقیماً در پیش‌نمونه تأیید شد.
- قلم: [Estedad](./typography-font.md)، با پشتیبان Noto Sans Arabic. برای انتشار نهایی،
  میزبانی مستقیم فایل قلم (self-host) به CDN گوگل ترجیح داده می‌شود — چون این پروژه دیگر
  وابستگی بیرونی برای بارگذاری صفحه نمی‌خواهد؛ CDN گوگل فقط برای همین پیش‌نمونه استفاده شد.

## مسئلهٔ میزبانی — هنوز باز

مخزن **خصوصی** است. GitHub Pages از مخزن خصوصی روی حساب رایگان قابل انتشار نیست. این تصمیم
دو راه پیش پا می‌گذارد، بدون انتخاب یکی — چون انتخاب به زمان‌بندی انتشار (نه به فناوری)
بستگی دارد:

1. مخزن هنگام رسیدن مراحل اصلی محتوا (طبق [priority-list.md](./priority-list.md)) عمومی
   شود و GitHub Pages به‌کار رود.
2. یا میزبانی جای دیگری (مثلاً Netlify/Vercel با دسترسی خصوصی به مخزن) صورت گیرد، بدون
   نیاز به عمومی‌کردن مخزن.
