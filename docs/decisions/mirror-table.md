# جدول قرینه‌سازی راست‌به‌چین — RTL mirror / do-not-mirror table

**وضعیت:** تصویب‌شده — [تیکت #14](https://github.com/vali-mohammadi/patternfly-design-fa/issues/14)
**منبع پژوهشی:** [research/area1-bidi-mirroring.md](../../research/area1-bidi-mirroring.md)

هیچ مرجع رسمی‌ای (نه UAX #9، نه CLDR، نه W3C) برای قرینه‌سازی آیکون‌ها وجود ندارد — این
سند، سیاست خودِ این پروژه است، نه نقل‌قول از یک استاندارد. هرجا منابع اختلاف داشتند، هر دو
سوی اختلاف ثبت شده.

## قرینه می‌شود (Mirror)

| عنصر | یادداشت |
|---|---|
| پیکان‌های جهت‌دار نسبی (بعدی، قبلی، برگشت) | قاعدهٔ اصلی، اجماع کامل منابع |
| نشانگرهای مسیر ناوبری (breadcrumb) و جداکننده‌هایشان | ترتیب مسیر هم باید معکوس شود، نه فقط نماد |
| چیدمان شبکه‌ای بر پایهٔ اولویت خواندن (مثلاً رتبه‌بندی بلوک‌های نقشهٔ حرارتی) | بالاترین اولویت در گوشهٔ **شروع خط** شبکه قرار می‌گیرد — در فارسی یعنی بالا-راست، نه بالا-چپ؛ همان منطق ترتیب مسیر راهنما و ستون‌های جدول |
| دکمه‌های تورفتگی متن (indent/outdent) | چون تورفتگی نسبت به جهت خواندن تعریف می‌شود |
| دکمه‌های پیمایش برگشت/جلو (ویزارد، مرورگر) | هم نماد، هم جای‌گیری فیزیکی |
| نوار پیشرفت خطی (progress bar) و ترتیب گام‌ها | ⚠️ استثنا: در عبری خطی می‌ماند؛ برای فارسی قرینه می‌شود |
| اسلایدر / ورودی بازه — حداقل مقدار به ابتدای سمت راست منتقل می‌شود | ⚠️ استثنا: اسلایدر پخش رسانه (scrubber) و بالانس فضایی (چپ/راست صدا) قرینه **نمی‌شوند** |
| دکمه‌های تغییردهنده، گروه دکمه، انتخابگر امتیاز | |
| کشو، ورق‌زدن، حرکت چرخشی (carousel)، انیمیشن جهت‌دار | جهت حرکت هم بخشی از قرینه‌سازی است |
| نوار پیمایش (scroll bar) به سمت چپ منتقل می‌شود | اختلاف جزئی در منابع؛ رفتار پیش‌فرض مرورگر با `dir` هماهنگ است |
| فیلد متنی — سمت نماد و ترازبندی متن | استثنا: متن بلندتر از ۲–۳ خط گاهی برای خوانایی راستچین نمی‌شود |
| علامت سؤال (؟) | باید با نویسهٔ فارسی `؟` (U+061F) بازطراحی شود، نه صرفاً قرینه‌سازی هندسی |

## قرینه نمی‌شود (Do NOT mirror)

| عنصر | یادداشت |
|---|---|
| ساعت و آیکون‌های ساعت | جهت عقربه قراردادی فیزیکی است، نه جهت خواندن |
| پرشدن دایره‌ای/دونات (نمودار دونات، نشانگر پیشرفت دایره‌ای) | ⚠️ **تصمیم اصیل (مرحلهٔ ۹الف):** پرشدگی از ساعت ۱۲ شروع و ساعتگرد حرکت می‌کند — همان قیاس ساعت بالا؛ جهت فیزیکی/قراردادی است، نه جهت خواندن، پس قرینه نمی‌شود. برخلاف **نوار پیشرفت خطی** که قرینه می‌شود (ردیف بالا) — تمایز بین دایره‌ای و خطی عمدی است |
| بازخوانی/رفرش (پیکان چرخشی ساعتگرد) | |
| علامت تیک (✓) | |
| نمودارها با محور زمان | **بحث‌برانگیز — بخش زیر را ببینید** |
| لوگو و نشان تجاری | |
| آیکون‌های حاوی متن یا عدد لاتین | چون `transform: scaleX(-1)` متن را هم برعکس می‌کند |
| اعداد | قرینه نمی‌شوند؛ اما باید **بومی‌سازی** شوند (ارقام فارسی) — سیاست کامل در [persian-encoding-fold.md](./persian-encoding-fold.md) |
| آیکون تلفن، پاکت نامه (غیرجهت‌دار) | برخلاف آیکون‌های تماس جهت‌دار (تماس ازدست‌رفته، برقرارشده) که قرینه می‌شوند |
| نُت موسیقی | |
| کنترل‌های پخش رسانه (پخش، توقف، جلو، عقب) و نوار پیشرفت رسانه | تقریباً اجماع کامل — بخش زیر را ببینید |
| کد، مسیر فایل، URL، ایمیل، شمارهٔ تلفن به‌صورت متن | جهت این‌ها باید صراحتاً LTR ثابت شود (`dir="ltr"`) |
| تصویر/عکس، مگر آنکه خود جهت را نشان دهد (مثلاً پیکان) | |

## موارد بحث‌برانگیز — نیاز به تصمیم موردی

- **آیکون بزرگنمایی/جست‌وجو:** دو منبع اصلی رفتار متضاد پیشنهاد می‌دهند و دلیل هر دو یکی است
  («ابزار باید راست‌دست به نظر برسد»). قاعده: به دسته‌ای که پس از قرینه‌سازی ظرف، آیکون در آن
  چپ‌دست از آب درمی‌آید، آیکون قرینه شود؛ در غیر این صورت ثابت بماند. تصمیم بر اساس بازبینی
  دارایی گرافیکی واقعی PatternFly، نه کپی از گوگل یا موزیلا.
- **واگرد/ازنو (Undo/Redo):** برخی منابع می‌گویند قرینه شود (چون گذشته/آینده در مسیر خواندن
  است)، برخی به‌خاطر شکل چرخشی نماد آن را در ردهٔ رفرش می‌گذارند. **تصمیم این پروژه: قرینه
  می‌شود** — چون معنای معنایی (گذشته/آینده) بر شکل چرخشی نماد اولویت دارد.
- **نمودار با محور زمان:** پیش‌فرض این پروژه **قرینه نکردن** محور کمّی/زمانی است (مطابق اپل،
  متریال و اکثریت ۵۸٪ رسانه‌های عربی‌زبان در پژوهش IEEE VIS 2024)، اما قاب نمودار (جای‌گیری
  legend، ترازبندی برچسب، سمت محور y در نمودارهای دسته‌ای) قرینه می‌شود. قرینه‌سازی محور زمان
  به‌صورت گزینه‌ای (opt-in) در سطح کامپوننت باقی می‌ماند، نه پیش‌فرض. یکدستی در یک صفحه الزامی
  است — ترکیب دو رویکرد در یک مجموعه نمودار ممنوع.

## پیاده‌سازی

- جهت را با `dir` روی `<html>` تنظیم کنید، نه با CSS.
- از خواص منطقی CSS استفاده کنید: `margin-inline-start/end`، `padding-inline-*`،
  `inset-inline-start`، `text-align: start` — نه `left`/`right`.
- برای آیکون‌های نامتقارن که باید قرینه شوند و متن ندارند: `transform: scaleX(-1)` قابل قبول
  است؛ برای آیکون‌هایی که پس‌زمینهٔ متنی دارند یا سایه/گرادیان جهت‌دار، دارایی گرافیکی جداگانه
  برای RTL تهیه شود.
- گزینهٔ `variant="playback"` مشابه `.playback` اپل برای اسلایدرها/نوارهای پیشرفتی که رفتار
  پخش رسانه دارند و نباید قرینه شوند.
